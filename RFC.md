# Request for Comments

This project is a demonstration and wants to learn from people who build or
run CRM systems.

## What we want to learn

- Is the domain model (contacts, accounts, leads, deals, campaigns, tickets,
  knowledge base) the right shape? What is missing or wrong?
- Are the scoring, forecasting, SLA, and ROI rules explainable and realistic?
- Are the consent-first marketing rules adequate for GDPR and PECR in your
  jurisdiction? (See [spec/regulatory.md](spec/regulatory.md).)
- How should it integrate with identity, email, and calendar systems?
  (See [spec/integrations.md](spec/integrations.md).)
- Is the API ergonomic for a front end you would build?

## Constructive feedback that helps most

- Concrete scenarios from real CRM practice, with what the software does and
  what you expected.
- Pointers to standards, regulations, or prior art we should follow.
- Specific wording changes to the spec, as a pull request or issue.

## How to send it

Open an issue titled `RFC: <topic>`, or email joel@joelparkerhenderson.com.
