## Executive Summary

The Contact Relationship Management (CRM) project is a **well-architected, specification-first** demonstration system that models enterprise CRM practices while maintaining strict boundaries with identity management. It is built as a **consumer application** in the family architecture, referencing identities (`person:`, `organization:`, `worker:`) from sibling services rather than owning them.

## 1. Project Overview

### 1.1 Purpose & Scope

**What CRM Provides:**
- **Sales Automation (SFA):** Contact/account management, lead scoring, pipeline/Kanban, forecasting
- **Marketing Automation:** Email campaigns, segments, nurture sequences, consent management
- **Customer Service & Support:** Ticketing, knowledge base, SLA tracking
- **Analytics & Reporting:** Win rate, pipeline value, forecast, campaign ROI, SLA health, CLV

**What CRM Does NOT Provide:**
- Identity registry (person/organization services own identities)
- Real email delivery in demo mode (simulated only)
- Billing/ERP functionality
- ML-based predictions (rules-only in v1)
- Telephony/CTI integration

### 1.2 Architecture

```
Browser (cookie session, no JS tokens)
        │
        ▼
UI (SvelteKit 3 + Svelte 5 Runes)
│─ BFF Proxy (server-side)
│─ Session management
│─ 8-locale i18n
        │ Authorization: Bearer v4.public.…
        ▼
Service (Rust + Axum + axa + sqlx + PostgreSQL 18)
│─ REST API (OpenAPI 3.0)
│─ Pure-core business rules
│─ ABAC authorization
│─ Audit trails & events
        │ EntityRef lookups (stub-first)
        ▼
Family Services:
│─ person-service (identities)
│─ organization-service (identities)
│─ worker-service (WPM: departments, employment events)
│─ project-portfolio-service (PPM: delivery ideas)
│─ authentication-service (sessions, tokens, attributes)
```
