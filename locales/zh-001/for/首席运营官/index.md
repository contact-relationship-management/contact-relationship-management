# 致首席运营官

> 工程简报，不是法律意见、认证或审计。内容反映截至 2026-10-11 代码仓库所显示的情况。本文不声称已获得任何认可。

## 运行它需要什么

服务由每个副本一个 Rust 进程，加上 PostgreSQL 18 和 Redis 组成；前端是一个 Node 进程。两者都以加固的非 root 容器镜像交付，基础镜像按摘要（digest）固定。运维手册见 [operations-runbook.md](../../../../spec/compliance/operations-runbook.md)。

## 规划时需要了解的运行事实

- **启动时安全失败。** 在生产环境中，如果认证被关闭、审计链不可用，或缺少必需的密钥和 `CRM_REDIS_URL`，服务会拒绝启动。配置错误的部署会停止，而不是敞开运行。
- **健康检查与指标。** `/_health`、`/_ping`、`/_readiness` 从不受限流影响，因此锁定不会导致健康的 Pod 被重启。指标位于 `/metrics.prom`。
- **滥用限制**在生产环境中默认开启：每个客户端每分钟 600 次请求，5 分钟内 10 次登录失败后锁定。它们通过 Redis 在各副本间共享；如果 Redis 故障，则退回为各副本各自计数。
- **紧急访问**（破玻璃）：任何已登录用户都可以获取最长 60 分钟、需说明理由的读取提权。每一次授权都必须由另一个人审查。**您必须运行的流程：** 对 `break_glass_granted` 审计记录设置告警，并查看未审查数量（管理页面 `/break-glass/review`）。
- **审计增长。** 读取操作会被审计，因此审计表会随流量增长。请为其规划保留期限。持续轮询的客户端会使其快速增长。

## 值得告知值班团队的已知限制

空闲登出在客户端实现；被撤销的令牌会立即被拒绝，但策略重新加载后，缓存的洞察最多需要 30 秒才会反映；破玻璃授权无法撤销，只能到期失效。
