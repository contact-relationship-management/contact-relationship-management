## 治理

- **决策权：** [GOVERNANCE.md](../../../../GOVERNANCE.md)、[MAINTAINERS.md](../../../../MAINTAINERS.md)、[CODEOWNERS](../../../../CODEOWNERS)。贡献和 AI 辅助的规则见 [CONTRIBUTING.md](../../../../CONTRIBUTING.md) 和 [AI_STATEMENT.md](../../../../AI_STATEMENT.md)。
- **变更控制：** 规范是权威来源；代码和测试都引用规范。CI 在两个平台上运行，`scripts/ci-check.sh` 可复现它。仓库中的规则：不要为了让某项通过而削弱测试或关卡。
- **披露：** [SECURITY.md](../../../../SECURITY.md) 是报告渠道。

## 风险

风险视图见[首席风险官简报](../首席风险官/index.md)。简言之：剩余风险最高的是未经外部检验的安全性（T42）、无法量化的无障碍状况（T48），以及数据分类——这由采用方决定。

## 合规：哪些是真实的，哪些不是

| 领域 | 现状 |
|---|---|
| 访问控制 | 已实现并经过测试：基于角色的脱敏、记录级检查、仅限管理员的运营读取、强制由第二人审查的破玻璃 |
| 审计 | 已实现并经过测试：哈希链、仅追加、在事务内写入，读取审计涵盖列表、交易列表和洞察。**部署方：** 在数据库之外锚定链头 |
| 隐私权利 | 已实现：主体访问导出、删除（存在未了结义务时被拒绝）、保留清理。**部署方：** 合法依据、保留计划、处理活动记录 |
| 加密 | 部分：两列使用本地密钥的字段级 AES-256-GCM，没有 KMS。静态加密和传输加密由部署方负责 |
| 供应链 | 已实现：`cargo audit`、`cargo deny`、`pnpm audit`、SBOM、按摘要固定的基础镜像。**差距：** 构建未签名，且摘要需要刷新计划（T49） |
| 无障碍 | 部分：自动 axe 扫描和如实的公开声明。**差距：** 没有人工审计（T48），译文未经审阅 |
| 独立保证 | **差距：** 没有（T42） |
| 电子邮件与营销法规 | 以同意为先的发送路径已实现；真实发送、处理者协议、退信和投诉处理均缺失（T39） |

## 需要在您的组织中指定负责人的控制措施

1. 对破玻璃授权的审查和告警（对 `break_glass_granted` 设置告警）。
2. 锚定审计链头，并按计划验证（`GET /api/audits/verify`）。
3. 备份与恢复的证据，以及密钥轮换演练。
4. 在您的身份提供方中处理入职、调动和离职。
5. 审计表的保留期限——它会随读取流量增长。
6. 像保护数据库一样保护 Redis：它保存着缓存的洞察数据。

## 应当拒绝签署的内容

任何声称系统合规、已认证、符合 HIPAA 或获 NHS 批准的说法。可以站得住脚的说法更克制：控制措施已映射，已实现的已测试，差距已列明并跟踪。
