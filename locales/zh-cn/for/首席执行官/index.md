# 致首席执行官

> 工程简报，不是法律意见、认证或审计。内容反映截至 2026-10-11 代码仓库所显示的情况。本文不声称已获得任何认可。

## 一段话说明决策

这是一个演示级的 CRM，安全与隐私基础异常扎实。它**尚未准备好**存放真实的患者或公民数据，仓库本身也这样说明（[plan.md](../../../../spec/plan.md)）。采用它，意味着决定为剩余的外部工作出资，而不是直接投入使用。

## 现有成果

- 一个可运行的 CRM，覆盖销售、营销、支持和分析，配有 Rust API 和 Web 前端，按书面规范构建。
- 以同意为先的营销；对不应看到敏感值的角色隐藏这些值的访问控制；能显示篡改的审计轨迹；面向隐私请求的主体访问与删除；以及有理由、限时并经审查的紧急（“破玻璃”）访问。
- 53 个已跟踪的工作项中已完成 48 个（[tasks.md](../../../../spec/tasks.md)）。

## 距离真实使用还差什么

| 阻碍 | 为什么重要 | 谁能解决 |
|---|---|---|
| 没有真实的电子邮件投递（T39） | 营销是模拟的；真实的服务商需要合同和数据处理协议 | 由您选择供应商；由法务签署 |
| 没有独立的安全测试（T42） | 医院和政府买家通常要求提供；我们自己的测试不具独立性 | 外部机构 |
| 没有人工无障碍审计（T48） | 公共机构必须发布自己能够负责的无障碍声明 | 使用辅助技术的人员 |
| 构建签名和 API 标准评审未完成（T49） | 采购清单会要求这两项 | 工程团队，并需决定密钥保管方式 |

## 由您决定的事项

1. **先进入哪个市场。** NHS 数字技术评估标准评估（[docs](../../../../docs/united-kingdom/national-health-service/digital-technology-assessment-criteria/2.0/index.md)）的结论是：该产品很可能不在 DTAC 适用范围内，而且在适用的部分会因缺乏组织层面的证据（指定的临床安全官、认证）而不通过。在投入资金前先选定路线。
2. **是否为独立保证出资**（T42、T48）。没有它，诚实的说法只能是“按高标准构建，但未经外部检验”。
3. **一旦持有真实数据，由谁承担风险。** 请参阅[首席风险官](../首席风险官/index.md)和[首席法务官](../首席法务官/index.md)的简报。

## 对外不要说什么

不要声称合规、已认证、“符合 HIPAA”或“获 NHS 批准”。证据包（[compliance](../../../../spec/compliance/index.md)）支持一个更克制、也更真实的说法：控制措施已映射，已实现的已测试，差距已列明。
