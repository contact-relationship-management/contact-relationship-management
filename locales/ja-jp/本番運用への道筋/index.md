# 本番運用への道筋

> Contact Relationship Management は本番運用の準備ができていません。このページでは、ここでいう本番運用とは何か、
> そして各部分がどこまで進んでいるかを示します。

このソフトウェアは合成データで動作します。実際のメールモードを設定しない限り、メールは模擬です。実際の
個人データを入力しないでください。

## 本番運用とは

本番環境では、実在する人々のデータを保持し、その人々に実際のメッセージを送ります。このプロジェクトでは、
次のすべてが必要です。

- **実際のサインイン。** すべてのリクエストが認証され、アクセス規則が導入先組織のロールに合致していること。
- **適法な送信。** 各メッセージに記録された同意があり、送信先のあらゆる地域の法律に基づく適法な根拠があること。
  また、バウンス、苦情、配信停止を処理する実際のメールプロバイダーを経由すること。
- **独立した保証。** プロジェクト外の人々がセキュリティとアクセシビリティをテストし、指摘事項が修正または
  受容されていること。
- **運用。** 復元を実施したバックアップ、監視、インシデント対応のプロセス、そして待機担当者。
- **安定性の証拠。** 導入先と同等のハードウェアで、現実的な負荷の下、エラーや速度低下なしに長時間稼働すること。

本番運用の準備状況は、導入ごとに判断されます。導入者は、自組織と自組織の受信者についてのみ、一部のゲートを
閉じることができます。このページの根拠となる技術的評価は [spec/plan.md](../../../spec/plan.md) です。未了の
ゲートは [spec/tasks.md](../../../spec/tasks.md) にあります。

## 準備状況

各パーセンテージは、2026-11-13 にタスク一覧から見積もった推定値であり、測定値ではありません。

- **認証とアクセス制御** (70%): PASETO トークンまたは Keycloak/OIDC によるサインイン、レコード単位の確認を伴う
  属性ベースのアクセス規則、認証なしでは起動を拒否する本番モードは構築済みです。実際の導入が自前の属性で
  これらを有効にした例はなく、強制マトリクスはまだすべてのハンドラーを網羅していません(CRM-G1)。
- **メール配信** (40%): 既定は模擬の送信機能で、SMTP 送信機能もあります。バウンスと苦情の Webhook や
  抑止リストを備えたメールプロバイダーのアダプターはありません(CRM-T39)。
- **データ保護と電子マーケティング法** (15%): 同意の記録、本人による開示、削除、保持は構築済みです。
  どの地域の法律もこのプロジェクトのために読み込まれておらず、実際の送信経路のレビューは未了です(CRM-G2、
  [regulatory](../../../spec/regulatory.md))。
- **独立したセキュリティ保証** (10%): ペネトレーションテストの範囲は作成済みです。ペネトレーションテスト、
  正式なリスク分析、認定はまだ行われていません(CRM-T42)。AI によるセキュリティ監査は独立した保証ではありません。
- **アクセシビリティ** (50%): WCAG 2.2 A および AA に対する axe-core の自動チェックが、すべてのページ
  ルートで合格しています。キーボードのみの操作、スクリーンリーダー、400% ズームによる手動監査は
  行われていません(CRM-T48)。
- **翻訳** (30%): 画面は 8 言語で利用できます。英語以外の言語の文字列は機械が書いたもので、
  話者によるレビューは受けていません。
- **運用** (30%): 運用ランブックは、バックアップと復元、鍵管理、保存時の暗号化、インシデント対応、ログ保持を
  扱っています。復元はテストされておらず、ランブックの本稼働チェックリストは未了です。
- **性能と安定性** (20%): 負荷テストと長時間の安定性テストはあります。安定性テストはデモ環境に対して
  2 分間実行されたのみで、長時間の実行も、本番相当のハードウェアでのベースラインもありません。
- **リリースの完全性** (85%): リリースイメージはマルチアーキテクチャで、署名と証明が付き、署名は検証に
  通ります。Actions とイメージはダイジェストで固定され、履歴は秘密情報についてスキャンされています。
  取得したリリースイメージの amd64 側は確認されておらず、2 つ目のコードホストもまだありません(CRM-T192)。
- **継続的インテグレーション** (100%): 1 つのスクリプトが、GitHub Actions と Woodpecker ですべてのチェックを
  実行します。2 つの Rust コードベースと UI にはそれぞれ 95% の行カバレッジの下限があり、ブラウザー、リント、
  サプライチェーン、変更行のミューテーション、週次の全体ミューテーションの各ゲートが整っています(CRM-T94)。
- **デモの安全策** (100%): ツアーの訪問者ごとにデモデータの個別のコピーが作られ、上限は 200 コピーです。
  ツアーは既定で無効です。提供するには `CONTACT_RELATIONSHIP_MANAGEMENT_DEMO_TOUR=on` を設定します(CRM-T92)。
