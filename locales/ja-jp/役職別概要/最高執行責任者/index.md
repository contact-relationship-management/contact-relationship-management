# 最高執行責任者向け

> 技術者向けの概要であり、法的助言、認証、監査ではありません。2026-10-11 時点でリポジトリが
> 示している内容を述べたものです。ここでは認定を主張するものは何もありません。

## 運用に必要なもの

サービスは、レプリカごとに 1 つの Rust プロセスと、PostgreSQL 18 および Redis で構成されます。フロントエンドは
Node プロセスです。どちらも、ダイジェストで固定されたベースイメージを用いた、堅牢化された非 root の
コンテナイメージとして提供されます。運用ランブックは
[operations-runbook.md](../../../../spec/compliance/operations-runbook.md) です。

## 計画に織り込むべき運用上の事実

- **起動時に安全側に倒れる。** 本番では、認証が無効な場合、監査チェーンが使えない場合、または必要な鍵と
  `CONTACT_RELATIONSHIP_MANAGEMENT_REDIS_URL` がない場合、サービスは起動を拒否します。設定を誤ったデプロイは、
  無防備なまま動くのではなく停止します。
- **ヘルスとメトリクス。** `/_health/live`、`/_health/ready`、`/_health/startup` はレート制限の対象に
  ならないため、ロックアウトで正常な Pod が再起動されることはありません。メトリクスは
  `/metrics.prom` にあります。
- **不正利用の制限**は本番で有効です。クライアントごとに 1 分あたり 600 リクエスト、5 分間に 10 回のサインイン
  失敗でロックアウトされます。これらは Redis を通じてレプリカ間で共有され、Redis が停止するとレプリカごとの
  カウントに切り替わります。
- **緊急アクセス**(ブレークグラス): サインイン中のユーザーは誰でも、理由を示して最長 60 分間、読み取り権限を
  昇格できます。すべての付与を別の人がレビューしなければなりません。
  **あなたが運用すべきプロセス:** `break_glass_granted` の監査行にアラートを設定し、未レビューの件数を
  確認します(管理ページ `/break-glass/review`)。
- **エラー**は 1 つの形式(RFC 9457 の `application/problem+json`、従来の `error` と `description` を維持)に
  統一されているため、ログの解析やアラート規則は `status` と `type` に頼れます。
- **監査の増加。** 読み取りは監査されるため、監査テーブルはトラフィックとともに増えます。その保持のための
  容量を見積もってください。ポーリングするクライアントがあると、急速に増えます。

## 残っている運用作業

| 項目 | 状態 |
|---|---|
| バックアップと復元の訓練、鍵ローテーションの予行演習 | ランブックに記載済み。**あなた**が実施して証拠を残す必要があります |
| 監査チェーンの先頭をデータベース外に固定する | あなたの責務。API は先頭のハッシュを報告します |
| 固定されたイメージダイジェストの更新 | Dependabot が毎週プルリクエストを作成します。**あなた**がレビューしてマージしないと、固定が古くなります |
| デプロイ前の署名付きリリースの検証 | コマンドはランブックにあります。ダイジェストでデプロイし、検証に失敗したイメージは拒否してください。最初のタグ付きリリースまでは未テストです |
| 実際のメールプロバイダー(T39) | 未了。インシデントと供給者の状況が変わります |
| Redis はインサイトのデータを保持する | データベースと同様に保護してください: TLS、パスワード、公開しない |

## 待機チームに伝えておくべき既知の制限

アイドル時のサインアウトはクライアント側で行われます。失効したトークンは即座に拒否されますが、ポリシーの
再読み込みは、キャッシュされたインサイトに最大 30 秒後に反映されます。ブレークグラスは取り消せず、
期限切れを待つしかありません。
