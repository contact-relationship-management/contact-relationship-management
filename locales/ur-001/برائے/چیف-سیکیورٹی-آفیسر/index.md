# چیف سیکیورٹی آفیسر کے لیے

> انجینئرنگ بریفنگ، نہ قانونی مشورہ، نہ تصدیق اور نہ آڈٹ۔ یہ بتاتی ہے کہ
> ریپوزٹری 2026-10-11 تک کیا دکھاتی ہے۔ یہاں کچھ بھی منظوری کا دعویٰ نہیں کرتا۔

## ایک پیراگراف میں سیکیورٹی کی پوزیشن

سروس **محفوظ طور پر ناکام ہوتی ہے**، رسائی کو کردار اور ریکارڈ کے لحاظ سے کنٹرول کرتی ہے، حساس اقدار ان کرداروں سے چھپاتی ہے جنہیں انہیں
نہیں دیکھنا چاہیے، اور چھیڑ چھاڑ ظاہر کرنے والا آڈٹ ٹریل رکھتی ہے۔ یہ کنٹرولز مصنفین نے نافذ کیے اور ٹیسٹ کیے ہیں۔ انہیں **کسی آزاد فریق نے
نہیں آزمایا** (T42)، اس لیے نیچے کے ہر بیان کو "بنایا گیا اور خود آزمایا گیا" سمجھیں، "تصدیق شدہ" نہیں۔

## کنٹرولز اور انہیں کہاں جانچنا ہے

| شعبہ | کیا موجود ہے | کہاں دیکھیں |
|---|---|---|
| تصدیق | PASETO v4.public کی آف لائن توثیق، اختیاری Keycloak؛ تصدیق بند ہو تو پیداوار شروع ہونے سے انکار کرتی ہے | [auth](../../../../spec/auth.md) |
| اجازت | صفت پر مبنی: پڑھنا، لکھنا، حذف کرنا، تباہ کن؛ ایک `mask` ذمہ داری؛ ریکارڈ کی سطح کی جانچ؛ صرف ایڈمن کے لیے آڈٹ، برقرار رکھنے اور بریک گلاس کا جائزہ | [auth](../../../../spec/auth.md)، پرسونا میٹرکس ٹیسٹ |
| ڈیٹا کا انکشاف | ریکارڈز، مجموعوں اور بصیرت پر چھپانا؛ اکاؤنٹ کی تفصیل میں ایک لیک ملی اور درست کی گئی (T47) | [tasks](../../../../spec/tasks.md) |
| ہنگامی رسائی | تحریری وجہ، 60 منٹ کی حد، صرف پڑھنا، دوسرے شخص کا لازمی جائزہ، آڈٹ شدہ، Redis کے ذریعے مشترک | بریک گلاس کے کام T44 |
| آڈٹ | اسی ٹرانزیکشن میں SHA-256 ہیش چین، صرف اضافہ کرنے والا ٹرگر، توثیق کا اینڈ پوائنٹ؛ پڑھنے کا آڈٹ | [audit](../../../../spec/audit.md) |
| غلط استعمال کے خلاف مزاحمت | شرح کی حد (600 فی منٹ) اور لاک آؤٹ (5 منٹ میں 10 ناکامیاں)، Redis کے ذریعے مشترک؛ پروبز مستثنیٰ | T43 |
| براؤزر اور ترسیل | ہیشز کے ساتھ سخت CSP، فریم کی ممانعت، `nosniff`، ریفرر پالیسی، بند CORS، محفوظ ہیڈرز؛ براؤزر JavaScript میں کوئی ٹوکن نہیں (BFF) | UI `hooks.server.ts` |
| ڈیٹا کا تحفظ | دو کالموں پر گھماؤ کے ساتھ AES-256-GCM؛ مقامی کلیدیں، KMS نہیں | T41 |
| سپلائی چین | `cargo audit`، `cargo deny`، `pnpm audit`، SBOM، ڈائجسٹ سے طے مضبوط غیر روٹ امیجز، ہفتہ وار Dependabot اپ ڈیٹس، ایسا ریلیز ورک فلو جو امیجز اور SBOM پر بغیر کلید کے دستخط کرتا ہے | [control-mapping](../../../../spec/compliance/control-mapping.md)، [operations-runbook](../../../../spec/compliance/operations-runbook.md) |
| غلطیاں | ہر غلطی ایک RFC 9457 مسئلہ دستاویز ہے؛ `401` قبول شدہ اسکیم کا نام بتاتا ہے | [api-lifecycle](../../../../spec/compliance/api-lifecycle.md) |
| میموری کی حفاظت | `forbid(unsafe_code)`، clippy pedantic | `src/lib.rs` |

## معلوم کمزوریاں (بیان کی گئی، چھپائی نہیں گئیں)

- **کوئی آزاد دخول ٹیسٹ یا خطرے کے ماڈل کی مشق نہیں** (T42)۔
  [dtac-supporting](../../../../spec/compliance/dtac-supporting.md) میں خطرے کا ماڈل ایک خلاصہ ہے، منظم ماڈل نہیں۔
- **ریلیز پر دستخط کسی حقیقی ریلیز پر نہیں چلے** (T49)۔ ورک فلو اور تصدیق کے احکامات موجود ہیں؛ ٹیگ پش ہونے تک وہ آزمائے نہیں گئے۔
  ایکشنز کمٹ ہیش سے طے ہیں۔
- **فیلڈ خفیہ کاری** دو کالموں کا احاطہ کرتی ہے، مقامی کلیدوں کے ساتھ، KMS کے بغیر۔
- **تباہ کن اقدامات سے پہلے دوبارہ تصدیق** بنی ہوئی نہیں ہے۔
- **Redis ذاتی ڈیٹا رکھتا ہے** (کیش شدہ بصیرت، اجازت کی کلیدیں) اور اس کی حفاظت ڈیٹا بیس کی طرح کرنی ہوگی: TLS، پاس ورڈ، عوامی رسائی نہیں۔
- **بریک گلاس** منسوخ نہیں ہو سکتا، صرف ختم ہو سکتا ہے، اور کوئی الرٹ نہیں لگا۔
- **شرح کی حد اور لاک آؤٹ** Redis ناکام ہو تو فی ریپلیکا گنتی پر آ جاتے ہیں؛ غیر تصدیق شدہ بالٹی فی پتہ ہے، اور `TRUSTED_PROXIES` میں
  درج نہ ہونے والی پراکسی کے پیچھے وہ پراکسی کا پتہ ہے، اس لیے حملہ آور دوسرے غیر تصدیق شدہ کال کرنے والوں کو لاک آؤٹ کر سکتا ہے۔ درست
  ٹوکن والے کال کرنے والے کو اس کے موضوع کے حساب سے گنا جاتا ہے۔
- **پالیسی کی دوبارہ لوڈنگ** کیش شدہ بصیرت میں 30 سیکنڈ تک کی تاخیر سے ظاہر ہوتی ہے۔
- **غیر فعالیت پر سائن آؤٹ** کلائنٹ کی طرف ہوتا ہے۔
- **Idempotency کلیدیں** API پر اختیاری ہیں (T52): جو کلائنٹ `Idempotency-Key` نہیں بھیجتا وہ دوبارہ کوشش کی گئی تخلیق سے ریکارڈ کے
  دہرانے سے محفوظ نہیں۔ ساتھ آنے والا UI ایک بھیجتا ہے۔

## تعینات کرنے والے کو کیا کرنا ہوگا

1. تصدیق آن رکھیں؛ پیداواری کلیدیں اور `CONTACT_RELATIONSHIP_MANAGEMENT_REDIS_URL` فراہم کریں۔
2. `break_glass_granted` پر الرٹ لگائیں اور اجازتوں کا بروقت جائزہ لیں۔
3. آڈٹ چین کے سرے کو ڈیٹا بیس سے باہر لنگر کریں اور شیڈول کے مطابق اس کی توثیق کریں (`GET /api/audits/verify`)۔
4. PostgreSQL اور Redis کی حفاظت کریں (نیٹ ورک، TLS، اسناد، بیک اپ، ذخیرے میں خفیہ کاری)؛ فراہم کردہ ٹاسک سے فیلڈ کلیدیں گھمائیں۔
5. Dependabot کی اپ ڈیٹس ضم کریں؛ سپلائی چین کا مرحلہ دوبارہ چلائیں؛ تعیناتی سے پہلے دستخط شدہ ریلیز کی تصدیق کریں۔
6. واقعات کے ردعمل کے لیے رن بک پر عمل کریں ([operations-runbook](../../../../spec/compliance/operations-runbook.md))۔

## کمزوریوں کا انتظام

رپورٹیں [SECURITY.md](../../../../SECURITY.md) کے ذریعے جاتی ہیں۔ کسی بھی حقیقی ڈیٹا سے پہلے اسٹیجنگ بلڈ پر آزاد ٹیسٹ (T42) کروائیں، اور
اہم تبدیلی کے بعد دوبارہ ٹیسٹ کریں۔

## سیکیورٹی کے تجویز کردہ اقدامات، ترتیب سے

1. آزاد دخول ٹیسٹ کا دائرہ طے کریں اور اسے کمیشن کریں (T42)۔
2. دستخط اور تصدیق ثابت کرنے کے لیے پہلا ریلیز ٹیگ پش کریں (T49)۔
3. بریک گلاس اور آڈٹ چین کی توثیق کی ناکامیوں کے لیے الرٹ لگائیں۔
4. ہر ماحول میں Redis کو TLS اور اسناد کے پیچھے رکھیں۔
5. KMS کی پشت پناہی والی فیلڈ کلیدیں اور فیلڈز کا وسیع احاطہ (T41 کا باقی حصہ)۔

[CTO کا خلاصہ](../چیف-ٹیکنالوجی-آفیسر/index.md) اور [CRO کا خلاصہ](../چیف-رسک-آفیسر/index.md) بھی دیکھیں۔
