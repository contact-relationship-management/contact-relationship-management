# چیف ٹیکنالوجی آفیسر کے لیے

> انجینئرنگ بریفنگ، نہ قانونی مشورہ، نہ تصدیق اور نہ آڈٹ۔ یہ بتاتی ہے کہ
> ریپوزٹری 2026-10-11 تک کیا دکھاتی ہے۔ یہاں کچھ بھی منظوری کا دعویٰ نہیں کرتا۔

## فن تعمیر

- **سروس:** Axum اور axa (sqlx 0.9) پر Rust، PostgreSQL 18، کیش، مشترک کاؤنٹرز اور بریک گلاس کی ترسیل کے لیے Redis۔
  `forbid(unsafe_code)`، clippy pedantic۔ رویے کا بنیادی ماخذ تصریح ہے
  ([index](../../../../spec/index.md)، [architecture](../../../../spec/architecture.md))۔
- **UI:** SvelteKit 3 / Svelte 5، بیک اینڈ فار فرنٹ اینڈ پراکسی تاکہ کوئی ٹوکن براؤزر JavaScript تک نہ پہنچے، ہیشز کے ساتھ سخت CSP۔
- **تصدیق:** PASETO v4.public کی آف لائن توثیق، اختیاری Keycloak؛ ایک مشترک انجن سے صفت پر مبنی رسائی کا کنٹرول (پڑھنا/لکھنا/حذف
  کرنا/تباہ کن اقدامات، ایک `mask` ذمہ داری، ریکارڈ کی سطح کی جانچ)۔
- **آڈٹ:** SHA-256 ہیش چین جو تبدیلی کی اسی ٹرانزیکشن میں لکھی جاتی ہے، صرف اضافہ کرنے والا ٹرگر، `GET /api/audits/verify` پر
  قابلِ توثیق۔
- **ڈیٹا کا تحفظ:** دو کالموں پر کلید گھمانے کے ساتھ AES-256-GCM فیلڈ خفیہ کاری؛ مقامی کلیدیں، KMS نہیں۔

## معیار کے شواہد

یونٹ ٹیسٹ (185)، ڈیٹا بیس ٹیسٹ (56، جن میں نفاذ، چھپانا، آڈٹ، صفحہ بندی، کیشنگ، idempotency، اسکیما کی جانچ شامل ہیں)، فرنٹ اینڈ یونٹ (106)
اور Playwright (98) بشمول axe رسائی پذیری اسکین۔ CI GitHub Actions اور Woodpecker پر fmt، clippy، ٹیسٹ، فرنٹ اینڈ بلڈ/لنٹ اور سپلائی
چین کا مرحلہ (`cargo audit`، `cargo deny`، `pnpm audit`، CycloneDX SBOM) چلاتی ہے۔ ایک ہی حکم اسے دہراتا ہے: `scripts/ci-check.sh`۔

## تکنیکی قرض اور دیانت دارانہ حدیں

- صفحہ بندی آفسیٹ کرسر استعمال کرتی ہے (اگر چلتے چلتے ڈیٹا بدلے تو قطاریں چھوٹ یا دہرائی جا سکتی ہیں)؛ جان بوجھ کر کل تعداد نہیں۔
- Idempotency کلیدیں API پر اختیاری ہیں (T52): دوبارہ کوشش سے ریکارڈ کے دہرانے سے بچنے کے لیے کلائنٹ کو تخلیق پر `Idempotency-Key`
  بھیجنی ہوگی۔ ساتھ آنے والا UI ہر تخلیق پر ایک بھیجتا ہے۔
- OpenAPI اسکیمے ہاتھ سے لکھے گئے ہیں۔ وہ درخواستوں، فہرستوں، تفصیلی پڑھنے، ڈیش بورڈز، بصیرت کے منظروں، آڈٹ، رازداری اور بریک گلاس
  کا احاطہ کرتے ہیں؛ حالت کی منتقلیاں اور اپ ڈیٹ شدہ ریکارڈ لوٹانے والے اپسرٹس بغیر قسم کے ہیں۔ جب کوئی راستہ اور دستاویز میل نہ کھائیں تو
  ایک ٹیسٹ ناکام ہوتا ہے، اور دوسرے حقیقی جوابات کو، چھپے ہوئے بھی، اسکیموں کے خلاف جانچتے ہیں
  ([gds-api-review](../../../../spec/compliance/gds-api-review.md))۔
- غلطیاں RFC 9457 مسئلہ دستاویزات ہیں (T54) جن میں پہلے کے `error` اور `description` ارکان برقرار ہیں؛ راؤٹر سے باہر کی پرتوں (سائز کی حد،
  ٹائم آؤٹ) کی غلطیاں تبدیل نہیں کی جاتیں۔ ورژن بندی اور متروک کرنے کی پالیسی [api-lifecycle](../../../../spec/compliance/api-lifecycle.md)
  ہے؛ `Deprecation` اور `Sunset` ہیڈرز طے ہیں مگر بنے نہیں۔
- فیلڈ خفیہ کاری دو کالموں کا احاطہ کرتی ہے؛ KMS کا انضمام نہیں۔
- متعدد ریپلیکا کی درستی کے لیے شرح کی حد اور کیش کی حالت کو Redis چاہیے۔
- بصیرت کے منظر کردار کے لحاظ سے چھپائے جاتے ہیں مگر ہر کال کرنے والے کے ٹوکن کے حساب سے 30 سیکنڈ کیش ہوتے ہیں۔
- تباہ کن اقدامات سے پہلے دوبارہ تصدیق کے لیے شناخت فراہم کنندہ کا کام درکار ہے۔

## تجویز کردہ تکنیکی ترتیب

1. KMS کی پشت پناہی والی فیلڈ کلیدیں اور فیلڈز کا وسیع احاطہ (T41 کا باقی حصہ)۔
2. بغیر کلید کے دستخط اور تصدیق ثابت کرنے کے لیے پہلی ریلیز ٹیگ کریں (T49)، اور کسی جائزہ کار سے API معیارات کا مسودہ جانچوائیں۔
3. پہلی متروکی کے ساتھ `Deprecation` اور `Sunset` ہیڈرز بنائیں۔
4. اسٹیجنگ بلڈ پر آزاد ٹیسٹ (T42) کمیشن کریں۔
