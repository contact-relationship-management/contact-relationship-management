# چیف آپریٹنگ آفیسر کے لیے

> انجینئرنگ بریفنگ، نہ قانونی مشورہ، نہ تصدیق اور نہ آڈٹ۔ یہ بتاتی ہے کہ
> ریپوزٹری 2026-10-11 تک کیا دکھاتی ہے۔ یہاں کچھ بھی منظوری کا دعویٰ نہیں کرتا۔

## اسے چلانے کے لیے کیا چاہیے

سروس ہر ریپلیکا کے لیے ایک Rust پروسیس اور اس کے ساتھ PostgreSQL 18 اور Redis ہے؛ فرنٹ اینڈ ایک Node پروسیس ہے۔ دونوں مضبوط
بنائے گئے، غیر روٹ کنٹینر امیجز کے طور پر آتے ہیں جن کی بنیادی امیجز ڈائجسٹ سے طے ہیں۔ آپریشنز رن بک
[operations-runbook.md](../../../../spec/compliance/operations-runbook.md) ہے۔

## وہ عملی حقائق جن کے مطابق منصوبہ بنائیں

- **آغاز پر محفوظ ناکامی۔** پیداوار میں سروس شروع ہونے سے انکار کرتی ہے اگر تصدیق بند ہو، آڈٹ چین ناقابلِ استعمال ہو، یا مطلوبہ کلیدیں اور
  `CONTACT_RELATIONSHIP_MANAGEMENT_REDIS_URL` غائب ہوں۔ غلط ترتیب والی تعیناتی کھلی چلنے کے بجائے رک جاتی ہے۔
- **صحت اور میٹرکس۔** `/_health/live`، `/_health/ready`، `/_health/startup` پر کبھی شرح کی حد نہیں لگتی، اس لیے لاک آؤٹ کسی
  صحت مند پوڈ کو دوبارہ شروع نہیں کر سکتا۔ میٹرکس `/metrics.prom` پر ہیں۔
- **غلط استعمال کی حدیں** پیداوار میں آن ہیں: فی کلائنٹ فی منٹ 600 درخواستیں، اور 5 منٹ میں 10 ناکام سائن ان کے بعد لاک آؤٹ۔ یہ
  Redis کے ذریعے ریپلیکاز میں مشترک ہیں؛ اگر Redis ناکام ہو تو یہ فی ریپلیکا گنتی پر آ جاتی ہیں۔
- **ہنگامی رسائی** (بریک گلاس): کوئی بھی سائن ان صارف 60 منٹ تک وجہ کے ساتھ پڑھنے کی بلندی لے سکتا ہے۔ ہر اجازت کا جائزہ کسی اور کو لینا
  ہوگا۔ **وہ عمل جو آپ کو چلانا ہے:** `break_glass_granted` آڈٹ قطاروں پر الرٹ لگائیں اور غیر جائزہ شدہ تعداد دیکھیں (ایڈمن صفحہ
  `/break-glass/review`)۔
- **غلطیاں** ایک ہی شکل کی ہیں (RFC 9457 `application/problem+json`، جس میں `error` اور `description` برقرار ہیں)، اس لیے لاگ
  کا تجزیہ اور الرٹ کے اصول `status` اور `type` پر بھروسا کر سکتے ہیں۔
- **آڈٹ کا بڑھنا۔** پڑھنے کا آڈٹ ہوتا ہے، اس لیے آڈٹ جدول ٹریفک کے ساتھ بڑھتا ہے۔ اس کے برقرار رکھنے کا حجم طے کریں۔ بار بار پوچھنے
  والا کلائنٹ اسے تیزی سے بڑھائے گا۔

## باقی آپریشنل کام

| مد | حالت |
|---|---|
| بیک اپ/بحالی کی مشقیں، کلید گھمانے کی مشق | رن بک میں لکھی ہیں؛ **آپ** کو انہیں چلانا اور ان کے شواہد رکھنے ہوں گے |
| آڈٹ چین کے سرے کو ڈیٹا بیس سے باہر لنگر کرنا | آپ کی ذمہ داری؛ API سرے کا ہیش بتاتی ہے |
| طے شدہ امیج ڈائجسٹس کی تازہ کاری | Dependabot ہفتہ وار پل ریکویسٹ کھولتا ہے؛ **آپ** کو انہیں جانچ کر ضم کرنا ہوگا ورنہ طے شدہ ڈائجسٹ پرانے ہو جائیں گے |
| تعیناتی سے پہلے دستخط شدہ ریلیز کی تصدیق | احکامات رن بک میں ہیں؛ ڈائجسٹ سے تعینات کریں، اور تصدیق میں ناکام امیج مسترد کریں۔ پہلی ٹیگ شدہ ریلیز تک آزمایا نہیں گیا |
| حقیقی ای میل فراہم کنندہ (T39) | کھلا؛ واقعات اور سپلائر کی تصویر بدل دیتا ہے |
| Redis بصیرت کا ڈیٹا رکھتا ہے | اس کی حفاظت ڈیٹا بیس کی طرح کریں: TLS، پاس ورڈ، عوامی رسائی نہیں |

## وہ معلوم حدیں جو آن کال ٹیم کو بتانا مفید ہے

غیر فعالیت پر سائن آؤٹ کلائنٹ کی طرف ہوتا ہے؛ منسوخ شدہ ٹوکن فوراً مسترد ہو جاتا ہے، لیکن پالیسی کی دوبارہ لوڈنگ کیش شدہ بصیرت میں 30
سیکنڈ تک کی تاخیر سے ظاہر ہوتی ہے؛ بریک گلاس منسوخ نہیں کیا جا سکتا، صرف ختم ہو سکتا ہے۔
