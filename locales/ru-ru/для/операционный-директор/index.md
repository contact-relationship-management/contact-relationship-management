# Для операционного директора

> Инженерная справка, а не юридическая консультация, сертификация или аудит. В ней изложено,
> что показывает репозиторий по состоянию на 2026-10-11. Ничто здесь не утверждает наличие аккредитации.

## Что нужно для эксплуатации

Сервис — это один процесс Rust на каждую реплику плюс PostgreSQL 18 и Redis; интерфейс — процесс Node. Оба
поставляются как укреплённые образы контейнеров без прав root с базовыми образами, закреплёнными по дайджесту.
Руководство по эксплуатации — [operations-runbook.md](../../../../spec/compliance/operations-runbook.md).

## Эксплуатационные факты, которые нужно учитывать

- **Безопасный отказ при запуске.** В продакшене сервис отказывается запускаться, если аутентификация выключена, если
  цепочка аудита непригодна или если отсутствуют необходимые ключи и `CONTACT_RELATIONSHIP_MANAGEMENT_REDIS_URL`.
  Неверно настроенное развёртывание останавливается, а не работает открытым.
- **Состояние и метрики.** `/_health/live`, `/_health/ready`, `/_health/startup` никогда не ограничиваются по частоте,
  поэтому блокировка не может перезапустить исправный под. Метрики — по адресу `/metrics.prom`.
- **Ограничения от злоупотреблений** в продакшене включены: 600 запросов в минуту на клиента и блокировка после 10
  неудачных входов за 5 минут. Они общие для реплик через Redis; если Redis недоступен, используются счётчики по каждой
  реплике.
- **Экстренный доступ** (break-glass): любой вошедший пользователь может получить обоснованное повышение прав на чтение
  до 60 минут. Кто-то другой должен проверить каждое разрешение. **Процесс, который вы должны выстроить:** оповещать о
  записях аудита `break_glass_granted` и проверять число непроверенных (страница администратора `/break-glass/review`).
- **Ошибки** имеют единую форму (RFC 9457 `application/problem+json`, с сохранёнными `error` и `description`), поэтому
  разбор журналов и правила оповещений могут полагаться на `status` и `type`.
- **Рост аудита.** Чтения аудируются, поэтому таблица аудита растёт вместе с трафиком. Рассчитайте для неё срок
  хранения. Клиент, который опрашивает сервис, будет увеличивать её быстро.

## Открытые эксплуатационные работы

| Пункт | Состояние |
| --- | --- |
| Учения по резервному копированию и восстановлению, репетиция ротации ключей | Описаны в руководстве; **вы** должны их провести и задокументировать |
| Закрепление головы цепочки аудита вне базы данных | Ваша обязанность; API сообщает хеш головы |
| Обновление закреплённых дайджестов образов | Dependabot еженедельно открывает запросы на слияние; **вы** должны проверять и сливать их, иначе закрепления устареют |
| Проверка подписанного выпуска перед развёртыванием | Команды есть в руководстве; развёртывайте по дайджесту и отклоняйте образ, не прошедший проверку. Не проверено до первого помеченного выпуска |
| Реальный почтовый провайдер (T39) | Открыто; меняет картину инцидентов и поставщиков |
| Redis хранит данные аналитики | Защищайте его как базу данных: TLS, пароль, отсутствие публичного доступа |

## Известные ограничения, о которых стоит сообщить дежурной команде

Выход при бездействии выполняется на стороне клиента; отозванный токен отклоняется сразу, но перезагрузка политики
отражается в кэшированной аналитике до 30 секунд; экстренный доступ нельзя отозвать, он может только истечь.
