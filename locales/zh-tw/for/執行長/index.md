# 致執行長

> 工程簡報，不是法律意見、認證或稽核。內容反映截至 2026-10-11 程式碼儲存庫所顯示的情況。本文不聲稱已獲得任何認可。

## 一段話說明決策

這是一個演示級的 CRM，安全與隱私基礎異常紮實。它**尚未準備好**存放真實的病患或公民資料，儲存庫本身也這樣說明（[plan.md](../../../../spec/plan.md)）。採用它，意味著決定為剩餘的外部工作出資，而不是直接投入使用。

## 現有成果

- 一個可執行的 CRM，覆蓋銷售、行銷、支援和分析，配有 Rust API 和 Web 前端，按書面規範建置。
- 以同意為先的行銷；對不應看到敏感值的角色隱藏這些值的存取控制；能顯示篡改的稽核軌跡；面向隱私請求的主體存取與刪除；以及有理由、限時並經審查的緊急（“破玻璃”）存取。
- 58 個已跟蹤的工作項中已完成 54 個（[tasks.md](../../../../spec/tasks.md)）。

## 距離真實使用還差什麼

| 阻礙 | 為什麼重要 | 誰能解決 |
|---|---|---|
| 沒有真實的電子郵件投遞（T39） | 行銷是模擬的；真實的服務商需要合約和資料處理協議 | 由您選擇供應商；由法務簽署 |
| 沒有獨立的安全測試（T42） | 醫院和政府買家通常要求提供；我們自己的測試不具獨立性 | 外部機構 |
| 沒有人工無障礙稽核（T48） | 公共機構必須發布自己能夠負責的無障礙聲明 | 使用輔助技術的人員 |
| 發布簽名已建置但尚未在真實發布上執行，也沒有評審人核對過 API 標準草稿（T49） | 採購清單會要求這兩項 | 工程團隊（打第一個發布標籤）；外部評審人 |

## 由您決定的事項

1. **先進入哪個市場。** NHS 數位技術評估標準評估（[docs](../../../../docs/united-kingdom/national-health-service/digital-technology-assessment-criteria/2.0/index.md)）的結論是：該產品很可能不在 DTAC 適用範圍內，而且在適用的部分會因缺乏組織層面的證據（指定的臨床安全官、認證）而不通過。在投入資金前先選定路線。
2. **是否為獨立保證出資**（T42、T48）。沒有它，誠實的說法只能是“按高標準建置，但未經外部檢驗”。
3. **一旦持有真實資料，由誰承擔風險。** 請參閱[風險長](../風險長/index.md)和[法務長](../法務長/index.md)的簡報。

## 對外不要說什麼

不要聲稱合規、已認證、“符合 HIPAA”或“獲 NHS 批准”。證據包（[compliance](../../../../spec/compliance/index.md)）支援一個更剋制、也更真實的說法：控制措施已對映，已實現的已測試，差距已列明。
