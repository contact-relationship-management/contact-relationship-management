## 執行它需要什麼

服務由每個副本一個 Rust 行程，加上 PostgreSQL 18 和 Redis 組成；前端是一個 Node 行程。兩者都以加固的非 root 容器映象交付，基礎映象按摘要（digest）固定。維運手冊見 [operations-runbook.md](../../../../spec/compliance/operations-runbook.md)。

## 規劃時需要了解的執行事實

- **啟動時安全失敗。** 在生產環境中，如果認證被關閉、稽核鏈不可用，或缺少必需的金鑰和 `CONTACT_RELATIONSHIP_MANAGEMENT_REDIS_URL`，服務會拒絕啟動。配置錯誤的部署會停止，而不是敞開執行。
- **健康檢查與指標。** `/_health/live`、`/_health/ready`、`/_health/startup` 從不受限流影響，因此鎖定不會導致健康的 Pod 被重啟。指標位於 `/metrics.prom`。
- **濫用限制**在生產環境中預設開啟：每個客戶端每分鐘 600 次請求，5 分鐘內 10 次登入失敗後鎖定。它們透過 Redis 在各副本間共享；如果 Redis 故障，則退回為各副本各自計數。
- **緊急存取**（破玻璃）：任何已登入使用者都可以獲取最長 60 分鐘、需說明理由的讀取提權。每一次授權都必須由另一個人審查。**您必須執行的流程：** 對 `break_glass_granted` 稽核記錄設定告警，並檢視未審查數量（管理頁面 `/break-glass/review`）。
- **錯誤格式**統一為一種（RFC 9457 `application/problem+json`，並保留 `error` 和 `description`），因此記錄解析和告警規則可以依賴 `status` 和 `type`。
- **稽核增長。** 讀取操作會被稽核，因此稽核表會隨流量增長。請為其規劃保留期限。持續輪詢的客戶端會使其快速增長。
