# Путь к продакшену

> Управление отношениями с контактами не готово к промышленной эксплуатации. На этой странице объясняется, что здесь
> означает продакшен и как далеко продвинулась каждая часть.

Программа работает на синтетических данных. Почта имитируется, пока не настроен режим реальной почты. Не вводите в
неё реальные персональные данные.

## Что означает продакшен

Промышленное развёртывание хранит данные реальных людей и отправляет им реальные сообщения. Для этого проекта нужно
всё перечисленное ниже:

- **Настоящий вход.** Каждый запрос аутентифицирован, а правила доступа соответствуют ролям организации, которая
  развёртывает систему.
- **Законная отправка.** Для каждого сообщения есть зафиксированное согласие и правовое основание по законам каждого
  места, куда оно отправляется, а само сообщение проходит через реального почтового провайдера, который обрабатывает
  недоставленные письма, жалобы и отписки.
- **Независимое подтверждение.** Люди вне проекта проверили безопасность и доступность, а выявленные замечания
  исправлены или приняты.
- **Эксплуатация.** Резервные копии, из которых проверено восстановление, мониторинг, процесс реагирования на
  инциденты и дежурный.
- **Свидетельства стабильности.** Длительные прогоны при реалистичной нагрузке на оборудовании, подобном
  развёртыванию, без ошибок и замедления.

Готовность к продакшену определяется для каждого развёртывания отдельно. Организация, развёртывающая систему, может
закрыть некоторые условия только для себя и своих получателей. Инженерная оценка, на которой основана эта страница, —
[spec/plan.md](../../../spec/plan.md). Открытые условия перечислены в [spec/tasks.md](../../../spec/tasks.md).

## Готовность

Каждый процент — оценка, сделанная 2026-11-13 по списку задач, а не измерение.

- **Аутентификация и управление доступом** (70%): Построены вход по токенам PASETO или Keycloak/OIDC, правила доступа на
  основе атрибутов с проверками на уровне записей и производственный режим, который отказывается запускаться без
  аутентификации. Ни одно реальное развёртывание не включило их со своими атрибутами, а матрица применения правил пока
  не охватывает все обработчики (CRM-G1).
- **Доставка почты** (40%): По умолчанию используется имитируемый отправитель, также есть SMTP-отправитель. Нет адаптера
  почтового провайдера с веб-хуками о недоставке и жалобах и нет списка подавления (CRM-T39).
- **Защита данных и законодательство об электронном маркетинге** (15%): Построены записи согласий, доступ субъекта,
  удаление и хранение. Законодательство ни одного региона для этого проекта не изучено, а проверка реального пути
  отправки остаётся открытой (CRM-G2, [нормативные требования](../../../spec/regulatory.md)).
- **Независимое подтверждение безопасности** (10%): Составлен объём тестирования на проникновение. Тестирование на
  проникновение, формальный анализ рисков и аккредитация не проводились (CRM-T42). Аудиты безопасности с помощью ИИ не
  являются независимым подтверждением.
- **Доступность** (50%): Автоматические проверки axe-core по WCAG 2.2 A и AA проходят на каждом маршруте страниц.
  Ручной аудит с использованием только клавиатуры, программ чтения с экрана и увеличения до 400% не проводился
  (CRM-T48).
- **Переводы** (30%): Интерфейс доступен на восьми языках. Строки на языках, отличных от английского, написаны машиной,
  и ни один носитель языка их не проверял.
- **Эксплуатация** (30%): Руководство по эксплуатации охватывает резервное копирование и восстановление, управление
  ключами, шифрование данных в состоянии покоя, реагирование на инциденты и хранение журналов. Восстановление не
  проверялось, а контрольный список запуска из руководства остаётся открытым.
- **Производительность и стабильность** (20%): Есть нагрузочные тесты и длительный тест стабильности. Тест стабильности
  работал две минуты на демонстрационном стенде; длительного прогона и эталонных замеров на оборудовании, подобном
  промышленному, нет.
- **Целостность выпусков** (85%): Образы выпусков многоархитектурные, подписанные и снабжены аттестациями, а их подписи
  проверяются. Действия и образы закреплены по дайджесту, а история проверяется на наличие секретов. Половина amd64 у
  загруженного образа выпуска не проверялась, а второго хостинга кода пока нет (CRM-T192).
- **Непрерывная интеграция** (100%): Один скрипт запускает все проверки в GitHub Actions и Woodpecker. Обе кодовые базы
  на Rust и интерфейс имеют нижнюю границу покрытия строк 95%; действуют проверки в браузере, линтер, проверка цепочки
  поставок, мутационное тестирование изменённых строк и еженедельное полное мутационное тестирование (CRM-T94).
- **Защита демонстрации** (100%): Каждый посетитель тура получает отдельную копию демонстрационных данных, не более 200
  копий. По умолчанию тур выключен; чтобы предложить его, задайте `CONTACT_RELATIONSHIP_MANAGEMENT_DEMO_TOUR=on`
  (CRM-T92).
