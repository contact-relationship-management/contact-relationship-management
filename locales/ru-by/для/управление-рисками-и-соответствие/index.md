# Управление, риски, соответствие

> Инженерная справка, а не юридическая консультация, сертификация или аудит. В ней изложено,
> что показывает репозиторий по состоянию на 2026-10-11. Ничто здесь не утверждает наличие аккредитации.

## С чего начать

Пакет доказательств — [spec/compliance](../../../../spec/compliance/index.md). Его основное правило — то, которого
следует требовать от команды: средство контроля **Реализовано** только тогда, когда код или конфигурация его применяют,
а тест или проверка его закрепляют; **Развёртывающий** — когда его должна обеспечить ваша организация; **Пробел** —
когда сегодня неверно ни то ни другое.

## Управление

- **Права принятия решений:** [GOVERNANCE.md](../../../../GOVERNANCE.md), [MAINTAINERS.md](../../../../MAINTAINERS.md),
  [CODEOWNERS](../../../../CODEOWNERS). Правила участия и использования ИИ изложены в
  [CONTRIBUTING.md](../../../../CONTRIBUTING.md) и [AI_STATEMENT.md](../../../../AI_STATEMENT.md).
- **Контроль изменений:** источник истины — спецификация; код и тесты ссылаются на неё. CI работает у двух
  провайдеров, а `scripts/ci-check.sh` воспроизводит его. Правило репозитория: не ослаблять тест или проверку, чтобы
  что-то прошло.
- **Раскрытие информации:** [SECURITY.md](../../../../SECURITY.md) — путь для сообщений.

## Риск

Обзор рисков есть в [справке для директора по рискам](../директор-по-рискам/index.md). Вкратце: наибольшие остаточные
риски — безопасность, не проверенная посторонними (T42), неоценённая доступность (T48) и классификация данных, которую
определяет принимающая сторона.

## Соответствие: что реально, а что нет

| Область | Позиция |
| --- | --- |
| Управление доступом | Реализовано и протестировано: ролевое скрытие, проверки на уровне записей, эксплуатационные чтения только для администратора, экстренный доступ с обязательной проверкой вторым человеком |
| Аудит | Реализовано и протестировано: цепочка хешей, только добавление, внутри транзакции, аудит чтений, включая списки, списки сделок и аналитику. **Развёртывающий:** закрепить голову цепочки вне базы данных |
| Права на конфиденциальность | Реализовано: выгрузка по запросу субъекта, удаление (отклоняется, пока обязательства открыты), очистка по сроку хранения. **Развёртывающий:** правовое основание, срок хранения, записи об обработке |
| Шифрование | Частично: AES-256-GCM на уровне полей в двух столбцах с локальными ключами, без KMS. Шифрование в состоянии покоя и при передаче — за развёртывающим |
| Цепочка поставок | Реализовано: `cargo audit`, `cargo deny`, `pnpm audit`, SBOM, базовые образы, закреплённые по дайджесту, обновления Dependabot. **Пробел:** рабочий процесс подписанного выпуска не запускался на реальном выпуске (T49) |
| Доступность | Частично: автоматические проверки axe и честное публичное заявление. **Пробел:** нет ручного аудита (T48), переводы не проверены |
| Независимое подтверждение | **Пробел:** отсутствует (T42) |
| Законодательство о почте и маркетинге | Реализован путь отправки, основанный на согласии; реальная отправка существует только как путь SMTP для разработки; есть ссылка для отписки, список подавления и подписанный веб-хук результатов, но ни один провайдер не интегрирован, а соглашение с обработчиком и юридическая проверка остаются открытыми (T39) |

## Средства контроля, которым нужен владелец в вашей организации

1. Проверка и оповещение о разрешениях экстренного доступа (оповещать о `break_glass_granted`).
2. Закрепление головы цепочки аудита и её проверка по расписанию (`GET /api/audits/verify`).
3. Свидетельства резервного копирования и восстановления и репетиция ротации ключей.
4. Приём, перемещение и увольнение сотрудников у вашего поставщика идентификации.
5. Хранение таблицы аудита, которая растёт вместе с трафиком чтения.
6. Защита Redis как базы данных: он хранит кэшированные данные аналитики.
7. Слияние обновлений Dependabot и проверка подписанного выпуска перед развёртыванием.

## Что отказываться подписывать

Любое утверждение, что система соответствует требованиям, сертифицирована, соответствует HIPAA или одобрена NHS.
Обоснованное утверждение уже: средства контроля сопоставлены, реализованные протестированы, а пробелы названы и
отслеживаются.
