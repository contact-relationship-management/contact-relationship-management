# 最高戦略責任者向け

> 技術者向けの概要であり、法的助言、認証、監査ではありません。2026-10-11 時点でリポジトリが
> 示している内容を述べたものです。ここでは認定を主張するものは何もありません。

## 戦略上の問い

これは何のためのものか。現状では、セキュリティ、プライバシー、監査の層が並外れて充実した、**仕様を第一とする
参照用 CRM** です。顧客のいる製品ではなく、成熟した CRM と競合するものでもありません
([COMPARISONS.md](../../../../COMPARISONS.md))。目の前にある選択は、参照用のままにするか、規制のある環境に
導入できるようにするために投資するかです。

## 本当に違うところ

| 強み | 重要になりうる理由 | どの程度確かか |
|---|---|---|
| 仕様が第一: 1 つの仕様が Rust のサービスと Svelte の UI の両方を動かす([spec](../../../../spec/index.md)) | 監査、移植、一貫性の維持が安く済む | 実在する。テストは仕様を引用している |
| 送信経路で強制される、同意を第一とするマーケティング | 医療や公共部門の購入者にとって厳格な要件 | 実在するが、実際の送信機能はまだない(T39) |
| 説明可能な、ルールに基づくリードスコアリングと予測 | 人に関する判断を正当化しなければならない購入者 | 実在する。機械学習は意図的に使っていない |
| 連絡先は ID サービスから取得し、複製しない | 保持する個人データが少なく、侵害の影響範囲が小さい | 実在する。そのサービスが存在することが前提 |
| 改ざんが分かる監査、ロール別のマスキング、理由を伴う緊急アクセス | 規制のある購入者が最初に尋ねる統制 | 実装およびテスト済み。独立した検証は未了 |

## 違わないところ

機能の幅です。見積、契約、電話、機械学習によるスコアリング、決済は範囲外です
([scope](../../../../spec/scope.md))。機能で CRM を選ぶ人は、別の製品を選ぶでしょう。

## 選択肢

| 選択肢 | 意味 | コストとリスク | 必要な証拠 |
|---|---|---|---|
| A. 参照用のままにする | 教材とパターン集として維持する | 最小。価値は評判 | 現状以上は不要 |
| B. 規制対象分野のニッチ | 未了の項目を仕上げ、医療や公的機関に販売または支援する | 最大。ベンダー、法的条件、外部テスト、継続的な保証が必要 | 独立したテスト(T42)、アクセシビリティ監査(T48)、実際のメール(T39) |
| C. 製品ではなく部品 | 監査チェーン、マスキング、ブレークグラスのパターンを再利用可能な部品として提供する | 中程度。パッケージ化とドキュメントが必要 | 切り出しの作業。新たな認証は不要 |

**推奨: 今は A を行い、コミットする前に B の最も安価な検証に資金を出してください。**
NHS の評価は、この製品はおそらく DTAC の対象外であると結論づけています
([評価](../../../../docs/united-kingdom/national-health-service/digital-technology-assessment-criteria/2.0/index.md))。
したがって、市場への道筋は定まっていません。まず、どの購入者がこれを必要とし、何を求めるのかを調べることに
費用をかけてください。誰も求めていない認証に費用をかけてはいけません。

## ロードマップ(証拠が示す順)

1. 独立したセキュリティテストと手動のアクセシビリティ監査(T42、T48): B がそもそも可能かどうかを
   決めます。
2. ベンダーとデータ処理条件が決まった後の実際のメールプロバイダー(T39)。送信機能の接続部分と SMTP 経路は
   あり、ローカルのテストサーバーに対して動作します。署名付きの配信停止リンク、抑止リスト、汎用の署名付き
   結果 Webhook もありますが、統合されたプロバイダーはまだありません([roadmap](../../../../spec/roadmap.md))。
3. 最初のタグ付きリリースでリリース署名を実証する(T49): 調達の最低条件です。ワークフローは構築済みですが、
   まだ実行されていません。
4. その後で初めて、ロードマップにある製品機能(アトリビューション、テリトリー、営業時間ベースの SLA 時計、
   公開ナレッジベースポータル)。

## 戦略上のリスク

- **事実以上のことを主張する。** 規制のある購入者を失う最も早い方法は、証拠の裏付けがない準拠の主張です。
  [GRC 向け概要](../ガバナンス・リスク・コンプライアンス/index.md)を参照してください。
- **保守。** セキュリティの作業に終わりはありません。依存関係の更新、ダイジェストの更新、鍵のローテーション、
  再テストが続きます。選択肢 B は、それにあなたを縛ります。
- **このリポジトリの外にある ID サービスへの依存。**
- **メンテナーが 1 人。** プロジェクトにはメンテナーが 1 人しかおらず、レビューの深さは 1 人分であると
  明記しています([MAINTAINERS.md](../../../../MAINTAINERS.md)、
  [GOVERNANCE.md](../../../../GOVERNANCE.md))。選択肢 B には、セキュリティの作業について責任を負える人が
  複数必要です。

## あなたが決めること

1. A、B、C のどれにするか、そしてその選択を見直す日付。
2. 最初に狙う購入者は誰か。費用をかける前に、対話を通じて見つけます。
3. 今、独立した保証に資金を出すかどうか([CEO 向け概要](../最高経営責任者/index.md)を参照)。
