# ガバナンス、リスク、コンプライアンス

> 技術者向けの概要であり、法的助言、認証、監査ではありません。2026-10-11 時点でリポジトリが
> 示している内容を述べたものです。ここでは認定を主張するものは何もありません。

## どこから始めるか

証拠パッケージは [spec/compliance](../../../../spec/compliance/index.md) です。その基本原則は、チームに
守らせるべきものです。統制が**実装済み**となるのは、コードまたは設定がそれを強制し、テストまたは検査が
それを固定している場合だけです。**導入者**は、あなたの組織が用意しなければならない場合、**ギャップ**は、
現時点でどちらにも当てはまらない場合です。

| ドキュメント | 用途 |
|---|---|

| [dpia-template](../../../../spec/compliance/dpia-template.md) | データ保護影響評価。このシステムのデータの流れがあらかじめ記入済み |

## ガバナンス

- **意思決定の権限:** [GOVERNANCE.md](../../../../GOVERNANCE.md)、[MAINTAINERS.md](../../../../MAINTAINERS.md)、
  [CODEOWNERS](../../../../CODEOWNERS)。貢献と AI 支援の規則は
  [CONTRIBUTING.md](../../../../CONTRIBUTING.md) と [AI_STATEMENT.md](../../../../AI_STATEMENT.md) にあります。
- **変更管理:** 仕様が情報源であり、コードとテストはそれを引用します。CI は 2 つのプロバイダーで動作し、
  `scripts/ci-check.sh` がそれを再現します。リポジトリ内の規則: 何かを通すためにテストやゲートを弱めない。
- **開示:** 報告経路は [SECURITY.md](../../../../SECURITY.md) です。

## リスク

リスクの見方は [CRO 向け概要](../最高リスク責任者/index.md)にあります。要するに、最大の残存リスクは、
外部の者によるテストを受けていないセキュリティ(T42)、定量化されていないアクセシビリティ(T48)、
そして導入者が判断するデータの分類です。

## コンプライアンス: 実際にあるものとないもの

| 領域 | 現状 |
|---|---|
| アクセス制御 | 実装およびテスト済み: ロール別のマスキング、レコード単位の確認、管理者専用の運用上の読み取り、別の人による必須のレビューを伴うブレークグラス |
| 監査 | 実装およびテスト済み: ハッシュで連鎖、追記専用、トランザクション内、一覧、ディール一覧、インサイトを含む読み取りの監査。**導入者:** チェーンの先頭をデータベース外に固定する |
| プライバシーの権利 | 実装済み: 本人開示のエクスポート、削除(義務が未了の間は拒否)、保持の一括処理。**導入者:** 適法根拠、保持スケジュール、処理の記録 |
| 暗号化 | 一部: 2 つの列に対するフィールド単位の AES-256-GCM。ローカル鍵で、KMS なし。保存時と通信中の暗号化は導入者の担当 |
| サプライチェーン | 実装済み: `cargo audit`、`cargo deny`、`pnpm audit`、SBOM、ダイジェストで固定されたベースイメージ、Dependabot の更新。**ギャップ:** 署名付きリリースのワークフローは実際のリリースで実行されていない(T49) |
| アクセシビリティ | 一部: 自動 axe スキャンと正直な公開声明。**ギャップ:** 手動監査がない(T48)、翻訳が未レビュー |
| 独立した保証 | **ギャップ:** なし(T42) |
| メールとマーケティングの法律 | 同意を第一とする送信経路は実装済み。実際の送信は開発用の SMTP 経路としてのみ存在する。配信停止リンク、抑止リスト、署名付きの結果 Webhook はあるが、統合されたプロバイダーはなく、処理者契約と法的レビューは未了(T39) |

## 組織内に担当者が必要な統制

1. ブレークグラスの付与に対するレビューとアラート(`break_glass_granted` にアラートを設定)。
2. 監査チェーンの先頭の固定と、定期的な検証
   (`GET /api/audits/verify`)。
3. バックアップと復元の証拠、および鍵ローテーションの予行演習。
4. ID プロバイダーでの入社、異動、退社の処理。
5. 読み取りトラフィックとともに増える監査テーブルの保持。
6. Redis をデータベースと同様に保護すること。キャッシュされたインサイトのデータを保持します。
7. Dependabot の更新をマージし、署名付きリリースをデプロイ前に検証すること。

## 承認を拒否すべきもの

システムが準拠している、認証されている、HIPAA に準拠している、または NHS に承認されているという主張は
すべて承認してはいけません。擁護できる言明は、より限定されたものです。統制は対応付けられ、実装済みのものは
テストされ、ギャップは明示されて追跡されている、ということです。
