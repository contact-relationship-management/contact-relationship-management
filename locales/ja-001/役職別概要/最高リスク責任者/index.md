# 最高リスク責任者向け

> 技術者向けの概要であり、法的助言、認証、監査ではありません。2026-10-11 時点でリポジトリが
> 示している内容を述べたものです。ここでは認定を主張するものは何もありません。

## リスクの状況

**総合: 規制対象のデータには準備ができていません。** ソフトウェアは現段階としては十分に統制されていますが、
主な残存リスクは、導入組織または外部の関係者しか提供できないテストとプロセスによって、軽減されていません。

## 主なリスク

| # | リスク | 評価の根拠 | リポジトリ内の軽減策 | 残存リスク |
|---|---|---|---|---|
| 1 | 未発見の脆弱性 | 独立したペネトレーションテストがない(T42) | 自前のテスト、サプライチェーンのゲート、厳格なヘッダーと CSP | テストされるまで**高** |
| 2 | 機微なフィールドが誤ったロールに開示される | 複雑なアクセス規則 | レコード、集計、インサイトに対するロール別マスキング、ペルソナ行列テスト、アカウント詳細で見つかり修正された漏えい(T47) | 中: マスキングはテスト済みだが、独立した検証はない |
| 3 | 緊急アクセスの内部者による不正利用 | ブレークグラスは読み取り権限を昇格する | 書面による理由、60 分の上限、読み取り専用、別の人による必須のレビュー、監査 | 中: アラートは未接続で、取り消しもできない |
| 4 | 監査証跡の改ざん | データベースへのアクセスが必要 | ハッシュチェーンと追記専用トリガー、最初の破断を報告 | 低〜中: 先頭のハッシュをデータベース外に固定する必要がある |
| 5 | 違法なマーケティング | 同意の誤り | 送信経路が同意を強制する(UI ではない)、変更不能な同意履歴 | 実際のプロバイダーを統合してレビューするまで中(T39) |
| 6 | 可用性 / 不正利用 | 公開 API | レート制限とロックアウト、Redis で共有 | 中: Redis が停止するとレプリカごとの制限に切り替わる |
| 7 | アクセシビリティへの不適合 | 公共部門の義務 | 自動 axe スキャン、正直なアクセシビリティ声明 | 手動監査(T48)まで**定量化されていない** |
| 8 | サプライチェーン | 依存関係とイメージ | `cargo deny/audit`、`pnpm audit`、SBOM、Dependabot が更新するダイジェスト固定、鍵なし署名のリリースワークフロー | 中: 署名は実際のリリースで実行されていない(T49) |
| 9 | 再試行による重複レコード | 冪等性キーは API では任意(T52) | キーを送るクライアントにはリプレイを返す。同梱の UI は常に送る | 低 |
| 10 | データの分類の誤り | 「連絡先」が何かは導入者が決める | 範囲に関する注記と DPIA テンプレート | あなた次第 |

## 性質上、未了のまま残るギャップ

T39(実際のメールプロバイダー)、T42(独立した保証)、T48(手動のアクセシビリティ監査)、T49(最初の署名付き
リリース、API 草案のレビュアーによる確認)。[tasks.md](../../../../spec/tasks.md) と
[plan.md](../../../../spec/plan.md) を参照してください。

## 推奨されるリスク対応

リスク 1、7、10 を正式に登録すること。実際のデータを扱う前に T42 を必須とすること。ブレークグラスの
レビューとアラートの担当者を決めること。監査チェーンの先頭を固定する頻度を決めること。
