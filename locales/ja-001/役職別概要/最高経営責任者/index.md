# 最高経営責任者向け

> 技術者向けの概要であり、法的助言、認証、監査ではありません。2026-10-11 時点でリポジトリが
> 示している内容を述べたものです。ここでは認定を主張するものは何もありません。

## 判断を 1 段落で

これはデモ水準の CRM で、セキュリティとプライバシーの基盤は並外れて強固です。実際の患者や市民のデータを
保持する準備は**できておらず**、リポジトリ自身もそう述べています([plan.md](../../../../spec/plan.md))。
これを採用するということは、残された外部作業に資金を出すと決めることであり、そのまま稼働させると決めることではありません。

## 現状あるもの

- 営業、マーケティング、サポート、分析にわたって動作する CRM。Rust の API とウェブのフロントエンドを備え、
  文書化された仕様に基づいて構築されています。
- 同意を第一とするマーケティング、見るべきでないロールから機密値を隠すアクセス制御、改ざんを示す監査証跡、
  プライバシー請求のための本人開示と削除、そして理由を伴い、時間が限られ、レビューされる緊急(「ブレークグラス」)アクセス。
- 追跡している 58 件の作業項目のうち 54 件が完了しています([tasks.md](../../../../spec/tasks.md))。

## 実利用までの障壁

| 障壁 | 重要な理由 | 解決できる人 |
|---|---|---|
| 実際のメール配信がない(T39) | マーケティングは模擬であり、実際のプロバイダーには契約とデータ処理契約が必要 | ベンダーはあなたが選び、法務が署名する |
| 独立したセキュリティテストがない(T42) | 病院や政府の購入者は通常これを求める。自前のテストは独立していない | 外部の企業 |
| 手動のアクセシビリティ監査がない(T48) | 公的機関は、責任を持てるアクセシビリティ声明を公表しなければならない | 支援技術を使う人々 |
| リリース署名は構築済みだが実際のリリースでは未実行で、API 標準の草案を確認したレビュアーもいない(T49) | 調達のチェックリストは両方を求める | エンジニアリング(最初のリリースにタグを付ける)、外部のレビュアー |

## あなたが決めること

1. **最初に狙う市場。** NHS Digital Technology Assessment Criteria の評価
   ([docs](../../../../docs/united-kingdom/national-health-service/digital-technology-assessment-criteria/2.0/index.md))は、
   この製品はおそらく DTAC の対象外であり、該当する項目では組織としての証拠(指名された臨床安全責任者、認証)が
   ないために不合格になると結論づけています。費用をかける前に進む道を選んでください。
2. **独立した保証に資金を出すかどうか**(T42、T48)。それがなければ、正直な主張は「高い水準で構築されたが、
   外部の者による検証は受けていない」です。
3. **実際のデータを保持した後、リスクを誰が負うか。** [CRO](../最高リスク責任者/index.md)と
   [CLO](../最高法務責任者/index.md)向けの概要を参照してください。

## 外部に向けて言ってはならないこと

準拠、認証、「HIPAA 準拠」、「NHS 承認」を主張してはいけません。証拠パッケージ
([compliance](../../../../spec/compliance/index.md))が裏付けるのは、より限定された真実の言明です。つまり、
統制は対応付けられ、実装済みのものはテストされ、ギャップは明示されている、ということです。
