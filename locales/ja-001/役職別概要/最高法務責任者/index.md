# 最高法務責任者向け

> 技術者向けの概要であり、法的助言、認証、監査ではありません。2026-10-11 時点でリポジトリが
> 示している内容を述べたものです。ここでは認定を主張するものは何もありません。

## 法的な立ち位置の概要

このリポジトリは**本番運用の準備ができておらず**、合成データを保持しています。いかなる制度への準拠も主張しません。
複数の制度を支える技術的機能を実装しており、導入者が追加すべきものを列挙しています
([regulatory](../../../../spec/regulatory.md))。

## 関係する制度

| 制度 | ソフトウェアが支えるもの | あなたが用意すべきもの |
|---|---|---|
| 英国/EU GDPR | 同意の履歴、本人開示のエクスポート、削除(未了の義務がある間は拒否)、保持の一括処理、データ最小化、読み取りの監査 | 目的ごとの適法根拠、DPIA([テンプレート](../../../../spec/compliance/dpia-template.md))、処理の記録、保持スケジュール、管理者と処理者の役割 |
| PECR / e プライバシー | 同意に基づく送信、即時の配信停止 | 実際の送信者のための、送信者の特定とソフトオプトインの判断 |
| HIPAA(米国の医療データの場合) | 監査統制、アクセス制御、完全性、伝送セキュリティの機能 | 事業提携契約、リスク分析、ポリシー、従業員研修。ソフトウェアだけで準拠することにはなりません |
| NHS DTAC / DCB0129/0160 | 証拠の草案([dtac-supporting](../../../../spec/compliance/dtac-supporting.md)) | 指名された臨床安全責任者、ハザードログ、認証。評価では、DTAC はおそらく適用されないとされています |
| アクセシビリティ(WCAG 2.2 AA、公共部門) | 自動チェックと正直な声明 | 準拠を主張する前の手動監査(T48) |
| 政府のセキュリティ(NIST 800-53、ISO 27001、Cyber Essentials) | 統制の対応表([control-mapping](../../../../spec/compliance/control-mapping.md)) | 認証と独立した保証 |

## まだ存在しない、必要になる契約

1. メールプロバイダーとのデータ処理契約と国際移転の条件(T39)。
2. ペネトレーションテスト企業との作業範囲記述書と秘密保持条件(T42)。
3. PostgreSQL、Redis、ログのホスティングと再委託先の条件。
4. ライセンス: [LICENSE.md](../../../../LICENSE.md) を参照してください。リポジトリには、
   セキュリティ、ガバナンス、AI 利用に関する声明も含まれています。

## 法務上の具体的な注意点

- **削除**は連絡先を匿名化し、未了のディール、チケット、有効なナーチャリング登録がある間は拒否されます。
  監査チェーンは操作の記録を保持するため、それが削除請求とどう関わるかは、DPIA で整理してください。
- マスクされたデータの**ブレークグラス**による読み取りが適法となるのは、あなたが文書化した根拠がある場合に
  限られます。理由欄は証拠であって、権限ではありません。
- リードの**スコアリング**: それが人に関する重要な判断に影響する場合、自動化された意思決定の規則が適用されます
  ([regulatory](../../../../spec/regulatory.md))。
- **API に関する約束:** [api-lifecycle](../../../../spec/compliance/api-lifecycle.md) は、API の変更を
  取り除く前の通知期間を 180 日と定めています。これはメンテナーの選択です。顧客がそれに頼ることになる場合は、
  契約に含めるべきかを判断してください。
- **公の主張:** 準拠、認証、承認を述べてはいけません。
