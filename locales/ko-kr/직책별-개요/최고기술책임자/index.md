# 최고기술책임자를 위해

> 엔지니어링 브리핑이며, 법률 자문, 인증, 감사가 아닙니다. 2026-10-11 현재 저장소가 보여 주는
> 내용을 서술합니다. 여기의 어떤 내용도 인증 취득을 주장하지 않습니다.

## 아키텍처

- **서비스:** Axum과 axa(sqlx 0.9) 기반의 Rust, PostgreSQL 18, 캐시, 공유 카운터, 비상 접근 전파를 위한 Redis.
  `forbid(unsafe_code)`, clippy pedantic. 동작의 기준 원천은 명세입니다
  ([index](../../../../spec/index.md), [architecture](../../../../spec/architecture.md)).
- **UI:** SvelteKit 3 / Svelte 5, 토큰이 브라우저 JavaScript에 절대 닿지 않도록 하는 backend-for-frontend 프록시, 해시를 쓰는
  엄격한 CSP.
- **인증:** 오프라인으로 검증하는 PASETO v4.public, 선택 사항인 Keycloak. 공유 엔진에서 오는 속성 기반 접근 제어(읽기/쓰기/
  삭제/파괴적 작업, `mask` 의무, 레코드 수준 검사).
- **감사:** 변경과 같은 트랜잭션에서 기록되는 SHA-256 해시 체인, 추가 전용 트리거, `GET /api/audits/verify`에서 검증
  가능.
- **데이터 보호:** 두 열에 키 교체를 갖춘 AES-256-GCM 필드 암호화. 로컬 키이며 KMS는 없음.

## 품질 증거

단위 테스트(185), 데이터베이스 테스트(집행, 마스킹, 감사, 페이지 나누기, 캐싱, 멱등성, 스키마 검사를 포함해 56), 프런트엔드
단위(106), axe 접근성 검사를 포함한 Playwright(98). CI는 GitHub Actions와 Woodpecker에서 fmt, clippy, 테스트, 프런트엔드
빌드/린트, 공급망 단계(`cargo audit`, `cargo deny`, `pnpm audit`, CycloneDX SBOM)를 실행합니다. 한 명령으로 이를 재현할
수 있습니다: `scripts/ci-check.sh`.

## 기술 부채와 정직한 한계

- 페이지 나누기는 오프셋 커서를 사용합니다(탐색 도중 데이터가 바뀌면 행이 건너뛰어지거나 반복될 수 있음). 총 개수는 설계상
  제공하지 않습니다.
- 멱등성 키는 API에서 선택 사항입니다(T52). 재시도가 레코드를 중복 생성하는 일을 막으려면 클라이언트가 생성 시
  `Idempotency-Key`를 보내야 합니다. 번들 UI는 모든 생성에서 이를 보냅니다.
- OpenAPI 스키마는 손으로 작성되었습니다. 요청, 목록, 상세 읽기, 대시보드, 인사이트 보기, 감사, 개인정보, 비상 접근을
  다루며, 상태 전이와 갱신된 레코드를 반환하는 upsert는 타입이 없습니다. 경로와 문서가 어긋나면 테스트가 실패하고, 다른
  테스트들은 가려진 응답을 포함한 실제 응답을 스키마와 대조합니다
  ([gds-api-review](../../../../spec/compliance/gds-api-review.md)).
- 오류는 RFC 9457 문제 문서(T54)이며 이전의 `error`와 `description` 멤버를 유지합니다. 라우터 바깥 계층의 오류(크기 제한,
  시간 초과)는 변환되지 않습니다. 버전 관리와 지원 중단 정책은
  [api-lifecycle](../../../../spec/compliance/api-lifecycle.md)이며, `Deprecation`과 `Sunset` 헤더는 명세되어 있지만
  구현되지 않았습니다.
- 필드 암호화는 두 열을 다루며, KMS 통합은 없습니다.
- 속도 제한과 캐시 상태가 여러 복제본에서 올바르려면 Redis가 필요합니다.
- 인사이트 보기는 역할별로 가려지지만 호출자 토큰별로 30초 동안 캐시됩니다.
- 파괴적 작업 전의 단계적 재인증은 신원 제공자 쪽 작업이 필요합니다.

## 권장 기술 순서

1. KMS 기반 필드 키와 더 넓은 필드 적용 범위(T41 잔여분).
2. 첫 릴리스에 태그를 붙여 키 없는 서명과 검증을 입증하고(T49), 검토자가 API 표준 초안을 확인하게 합니다.
3. 첫 지원 중단과 함께 `Deprecation`과 `Sunset` 헤더를 구현합니다.
4. 스테이징 빌드를 대상으로 독립적인 테스트(T42)를 의뢰합니다.
