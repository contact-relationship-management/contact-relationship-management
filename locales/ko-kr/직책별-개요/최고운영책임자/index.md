# 최고운영책임자를 위해

> 엔지니어링 브리핑이며, 법률 자문, 인증, 감사가 아닙니다. 2026-10-11 현재 저장소가 보여 주는
> 내용을 서술합니다. 여기의 어떤 내용도 인증 취득을 주장하지 않습니다.

## 이것을 운영하는 데 필요한 것

서비스는 복제본당 하나의 Rust 프로세스에 PostgreSQL 18과 Redis를 더한 것이며, 프런트엔드는 Node 프로세스입니다. 둘 다
기본 이미지를 다이제스트로 고정한, 보안이 강화된 비루트 컨테이너 이미지로 제공됩니다. 운영 런북은
[operations-runbook.md](../../../../spec/compliance/operations-runbook.md)입니다.

## 계획에 반영해야 할 운영 사실

- **시작 시 안전하게 실패합니다.** 운영 환경에서 인증이 꺼져 있거나, 감사 체인을 쓸 수 없거나, 필요한 키와
  `CONTACT_RELATIONSHIP_MANAGEMENT_REDIS_URL`이 없으면 서비스는 시작을 거부합니다. 잘못 구성된 배포는 열린 채 실행되는
  대신 멈춥니다.
- **상태 확인과 지표.** `/_health/live`, `/_health/ready`, `/_health/startup`은 속도 제한을 받지 않으므로, 잠금 때문에
  정상 파드가 재시작되는 일은 없습니다. 지표는 `/metrics.prom`에 있습니다.
- **남용 한도**는 운영 환경에서 켜져 있습니다. 클라이언트당 분당 600건의 요청, 그리고 5분 동안 로그인 10회 실패 시 잠금입니다.
  이 한도는 Redis를 통해 복제본 간에 공유되며, Redis가 실패하면 복제본별 집계로 되돌아갑니다.
- **비상 접근**(break-glass): 로그인한 모든 사용자는 사유를 밝히고 최대 60분 동안 읽기 권한 상승을 받을 수 있습니다. 모든
  부여는 다른 사람이 검토해야 합니다. **귀하가 운영해야 하는 절차:** `break_glass_granted` 감사 행에 경보를 걸고, 검토되지
  않은 건수를 확인하세요(관리자 페이지 `/break-glass/review`).
- **오류**는 하나의 형식입니다(RFC 9457 `application/problem+json`, `error`와 `description` 유지). 따라서 로그 파싱과
  경보 규칙은 `status`와 `type`에 의존할 수 있습니다.
- **감사 증가.** 읽기도 감사되므로 감사 테이블은 트래픽에 따라 커집니다. 이에 맞춰 보존 기간을 정하세요. 폴링하는 클라이언트는
  이를 빠르게 키웁니다.

## 남은 운영 작업

| 항목 | 상태 |
|---|---|
| 백업/복원 훈련, 키 교체 리허설 | 런북에 작성되어 있으며, **귀하가** 실행하고 증거를 남겨야 합니다 |
| 감사 체인 헤드를 데이터베이스 밖에 고정 | 귀하의 의무이며, API는 헤드 해시를 보고합니다 |
| 고정된 이미지 다이제스트 갱신 | Dependabot이 매주 풀 요청을 열며, **귀하가** 검토하고 병합하지 않으면 고정이 낡아집니다 |
| 배포 전에 서명된 릴리스 검증 | 명령은 런북에 있습니다. 다이제스트로 배포하고, 검증에 실패한 이미지는 거부하세요. 첫 태그 릴리스 전까지는 테스트되지 않았습니다 |
| 실제 이메일 제공자 (T39) | 열려 있으며, 사고와 공급업체 구도를 바꿉니다 |
| Redis는 인사이트 데이터를 보관합니다 | 데이터베이스처럼 보호하세요. TLS, 비밀번호, 공개 노출 금지 |

## 대기 팀에 알릴 만한 알려진 한계

유휴 로그아웃은 클라이언트 측에서 이루어집니다. 폐기된 토큰은 즉시 거부되지만, 정책 재적재는 캐시된 인사이트에 최대 30초
뒤에 나타납니다. 비상 접근은 폐기할 수 없고 만료만 됩니다.
