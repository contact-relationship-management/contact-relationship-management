# 최고경영자를 위해

> 엔지니어링 브리핑이며, 법률 자문, 인증, 감사가 아닙니다. 2026-10-11 현재 저장소가 보여 주는
> 내용을 서술합니다. 여기의 어떤 내용도 인증 취득을 주장하지 않습니다.

## 한 단락으로 보는 결정

이것은 보안과 개인정보 보호의 기반이 이례적으로 탄탄한 데모 수준의 CRM입니다. 실제 환자나 시민의 데이터를 보관할 준비가
**되어 있지 않으며**, 저장소 스스로도 그렇게 밝히고 있습니다([plan.md](../../../../spec/plan.md)). 이것을 도입한다는 것은
켜기로 결정하는 것이 아니라, 남은 외부 작업에 자금을 대기로 결정하는 것입니다.

## 있는 것

- 영업, 마케팅, 지원, 분석 전반에 걸쳐 작동하는 CRM. 문서화된 명세에 따라 만들어진 Rust API와 웹 프런트엔드를 갖추고
  있습니다.
- 동의를 우선하는 마케팅, 민감한 값을 볼 수 없어야 하는 역할에게 가려 주는 접근 제어, 변조를 드러내는 감사 추적, 개인정보
  요청을 위한 정보 주체 열람과 삭제, 그리고 사유를 밝히고 시간이 제한되며 검토를 거치는 긴급("비상 접근", break-glass)
  접근.
- 추적 중인 작업 항목 58건 중 54건이 완료되었습니다([tasks.md](../../../../spec/tasks.md)).

## 이것과 실제 사용 사이에 놓인 것

| 장애물 | 중요한 이유 | 해결할 수 있는 주체 |
|---|---|---|
| 실제 이메일 전달 없음 (T39) | 마케팅은 시뮬레이션이며, 실제 제공자에는 계약과 데이터 처리 계약이 필요합니다 | 업체는 귀하가 선택하고, 법무가 서명합니다 |
| 독립적인 보안 테스트 없음 (T42) | 병원과 정부 구매자는 대개 이를 요구하며, 우리 자체 테스트는 독립적이지 않습니다 | 외부 업체 |
| 수동 접근성 감사 없음 (T48) | 공공 기관은 책임질 수 있는 접근성 성명을 공표해야 합니다 | 보조 기술을 쓰는 사람들 |
| 릴리스 서명은 만들어졌지만 실제 릴리스에서 실행된 적이 없고, 검토자가 API 표준 초안을 확인하지 않았습니다 (T49) | 조달 체크리스트는 둘 다 요구합니다 | 엔지니어링(첫 릴리스 태그), 외부 검토자 |

## 귀하의 몫인 결정

1. **어느 시장부터 갈 것인가.** NHS Digital Technology Assessment Criteria 평가
   ([docs](../../../../docs/united-kingdom/national-health-service/digital-technology-assessment-criteria/2.0/index.md))는
   이 제품이 아마도 DTAC 범위 밖에 있으며, 조직적 증거(지명된 임상 안전 책임자, 인증)가 없어 적용되는 항목에서 불합격할
   것이라고 결론짓습니다. 비용을 쓰기 전에 경로를 정하세요.
2. **독립적인 보증에 자금을 댈 것인가** (T42, T48). 그렇지 않다면 정직한 주장은 "높은 기준으로 만들었으나 외부인이 시험하지
   않았다"입니다.
3. **실제 데이터를 보관하게 되면 누가 위험을 책임질 것인가.** [CRO](../최고위험책임자/index.md)와
   [CLO](../최고법무책임자/index.md) 개요를 참고하세요.

## 외부에 말하지 말아야 할 것

규정 준수, 인증, "HIPAA 준수", "NHS 승인"을 주장하지 마세요. 증거 묶음([compliance](../../../../spec/compliance/index.md))이
뒷받침하는 것은 더 좁고 참인 진술입니다. 통제 항목을 매핑했고, 구현된 것은 테스트했으며, 공백은 이름을 붙여 두었다는 것입니다.
