# 최고위험책임자를 위해

> 엔지니어링 브리핑이며, 법률 자문, 인증, 감사가 아닙니다. 2026-10-11 현재 저장소가 보여 주는
> 내용을 서술합니다. 여기의 어떤 내용도 인증 취득을 주장하지 않습니다.

## 위험 입장

**전반적으로: 규제 대상 데이터에 쓸 준비가 되어 있지 않습니다.** 이 소프트웨어는 현 단계에 비해 잘 통제되어 있지만, 주요 잔여
위험은 도입 조직이나 외부 당사자만 제공할 수 있는 테스트와 절차로 완화되지 않았습니다.

## 주요 위험

| # | 위험 | 평가 근거 | 저장소 내 완화 | 잔여 |
|---|---|---|---|---|
| 1 | 발견되지 않은 취약점 | 독립적인 침투 테스트 없음 (T42) | 자체 테스트, 공급망 관문, 엄격한 헤더/CSP | 테스트 전까지 **높음** |
| 2 | 민감한 필드가 잘못된 역할에 노출됨 | 복잡한 접근 규칙 | 레코드, 집계, 인사이트에 대한 역할 기반 마스킹, 페르소나 매트릭스 테스트, 계정 상세에서 발견되어 수정된 유출 (T47) | 중간: 마스킹은 테스트되었지만 독립적으로 검증되지 않음 |
| 3 | 내부자의 비상 접근 오용 | 비상 접근이 읽기 권한을 높임 | 서면 사유, 60분 상한, 읽기 전용, 필수 제2인 검토, 감사됨 | 중간: 연결된 경보 없음, 폐기 불가 |
| 4 | 감사 추적 변경 | 데이터베이스 접근이 필요 | 해시 체인과 추가 전용 트리거, 첫 단절 지점을 보고 | 낮음-중간: 헤드 해시를 데이터베이스 밖에 고정해야 함 |
| 5 | 불법 마케팅 | 동의 오류 | UI가 아니라 발송 경로가 동의를 집행, 변경 불가능한 동의 이력 | 실제 제공자가 통합되고 검토되기 전까지 중간 (T39) |
| 6 | 가용성 / 남용 | 공개 API | Redis를 통해 공유되는 속도 제한과 잠금 | 중간: Redis가 실패하면 한도가 복제본별로 되돌아감 |
| 7 | 접근성 비준수 | 공공 부문의 의무 | 자동 axe 검사, 정직한 접근성 성명 | 수동 감사 전까지 **정량화되지 않음** (T48) |
| 8 | 공급망 | 의존성과 이미지 | `cargo deny/audit`, `pnpm audit`, SBOM, Dependabot이 갱신하는 다이제스트 고정, 키 없는 서명 릴리스 워크플로 | 중간: 서명이 실제 릴리스에서 실행된 적 없음 (T49) |
| 9 | 재시도로 인한 중복 레코드 | 멱등성 키는 API에서 선택 사항 (T52) | 키를 보내는 클라이언트에 대한 재생, 번들 UI는 항상 보냄 | 낮음 |
| 10 | 데이터 오분류 | 무엇이 "연락처"인지는 배포자가 결정 | 범위 메모와 DPIA 템플릿 | 귀하에게 달려 있음 |

## 성격상 열려 있을 수밖에 없는 공백

T39(실제 이메일 제공자), T42(독립적인 보증), T48(수동 접근성 감사), T49(첫 서명 릴리스, API 초안에 대한 검토자의 확인).
[tasks.md](../../../../spec/tasks.md)와 [plan.md](../../../../spec/plan.md)를 참고하세요.

## 권장 위험 조치

위험 1, 7, 10을 공식적으로 등록하고, 실제 데이터 이전에 T42를 요구하며, 비상 접근 검토와 경보의 책임자를 정하고, 감사 헤드
고정 주기를 정하세요.
